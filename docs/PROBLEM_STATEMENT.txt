# AI usage disclosure

## Tool used
Claude (Anthropic), via the claude.ai chat interface. No other AI tools were used.
The application itself also calls the Claude API at runtime for the incident copilot .

## Where AI accelerated my work
Claude produced almost all first-draft code in this repository: the physics model, the data generator and validation, the MySQL schema and loader, the feature builder and classifier, the Flask API, the React UI and CSS, and the first drafts of the README and design notes. It also proposed the project framing (process fault vs sensor fault) and the evaluation approach.

## Where I relied on it heavily
Essentially all implementation. I am not claiming the code was hand-written. The value I added is in running, checking, debugging and understanding it .

## What I personally did, reviewed, changed and validated
- Ran the full stack on my own machine (Windows, PowerShell, MySQL 8): data generation, MySQL load, API, UI.
- Hit and fixed three real errors: (1) Linux `export` syntax does not work in PowerShell, so I switched to `$env:` variables; (2) the schema loader skipped the first `CREATE TABLE` because of a leading comment, which broke the foreign key to `facility`; (3) the API crashed serializing plain dates to JSON (`date.isoformat()` takes no `sep` argument). Each fix was applied to the code.
- Exercised the What-if simulator and checked the stored run in MySQL (`SIM-2026-000015`, the first run written through the API).
- Checked the repository for secrets before publishing (none; credentials come from environment variables).
- read  `ml.py` line by line; ran the leak / blockage / degradation scenarios; reviewed every endpoint in `app.py`.
